## О проекте

**Dream-Team** — сайт для поиска команды на хакатон среди студентов.

Что умеет (целевая функциональность):
- Просмотр анкет студентов, которые ищут команду: стек, университет, курс, о себе, статус.
- Публикация запроса команды: «нужно N человек с таким-то стеком/ролью».
- Связь с автором анкеты/запроса (кнопка «Написать» / «Познакомиться»).
- Регистрация и вход (отдельные действия: «Войти» и «Зарегистрироваться»).

Язык интерфейса: **русский**.

Сейчас фронтенд работает **на демо-данных** (`src/data/demoListings.ts`). API бэкенда в клиент **ещё не подключён**. Вход и регистрация — заглушка в `AuthDialog` (логин показывается в шапке, пароль не хранится). Создание анкеты и кнопки «Откликнуться» / «Позвать в команду» — тосты, в каталог ничего не пишется.

Параллельная работа (октябрь 2026):
- **Илья** приводит `backend/` к схеме Бахтияра (модели, `DATA_BASE_URL`, UUID в URL, тело `POST /listings`). Это его зона.
- **Игорь** делает **редизайн** интерфейса. Пока API не починен, редизайн остаётся на демо-данных и не ждёт бэкенд.

## Стек

- Frontend: **React 19 + TypeScript + Vite** (папка `frontend/`)
- Backend: **FastAPI + SQLAlchemy + Pydantic** (папка `backend/`)
- БД: **PostgreSQL 16** (локально в Docker через `docker-compose.yml`; образ `postgres:16-alpine`)
- Контейнеризация: **Docker Compose** (пока поднимает только БД)

## База данных и локальное окружение (Docker)

Для локальной разработки развёрнут контейнер с PostgreSQL:

- **Конфигурация**: в корне проекта лежат `docker-compose.yml` и `.env.example`.
- **Безопасность**: реальный файл `.env` внесён в `.gitignore` и **никогда не коммитится**.
- **Контейнер**: имя `dream_team_db`, образ `postgres:16-alpine`, том данных `pgdata`, healthcheck (`pg_isready`).
- **База и пользователь**: БД `dream_team_db`, пользователь `postgres`.
- **Порты**: привязка `127.0.0.1:5433:5432`. На хосте порт **`5433`**, потому что `5432` может быть занят локальным PostgreSQL / pgAdmin. База открыта только для `127.0.0.1`.
- **Первый запуск контейнера**: папка `database/migrations/` смонтирована в `/docker-entrypoint-initdb.d`, SQL выполняется при инициализации пустого тома.
- **Повторное применение** на уже существующей базе: `database/migrate.sh` (ведёт таблицу `schema_migrations`). Скрипт по умолчанию ходит на `localhost:5432` — для Docker-БД передай `DB_PORT=5433`.

### Команды для запуска

```powershell
Copy-Item .env.example .env     # затем указать свой пароль POSTGRES_PASSWORD
docker compose up -d            # запуск контейнера в фоне
docker compose ps               # проверка: статус должен быть (healthy)
```

`.env.example` сейчас содержит только переменные Docker:

```
POSTGRES_DB=dream_team_db
POSTGRES_USER=postgres
POSTGRES_PASSWORD=change_me
```

У бэкенда отдельная переменная **`DATA_BASE_URL`** (см. `backend/database.py`). В `.env.example` её пока нет — для локального запуска её нужно добавить в свой `.env`.

### Подключение (для Backend и GUI-клиентов)

- **Строка подключения**:
  `postgresql://postgres:<пароль_из_.env>@localhost:5433/dream_team_db`
- **Параметры для pgAdmin / DBeaver**:
  - Host: `127.0.0.1` (или `localhost`)
  - Port: `5433` (не 5432!)
  - Username: `postgres`
  - Maintenance database: `dream_team_db`
  - Password: пароль из вашего локального `.env`

### Схема (миграции)

Файлы в `database/migrations/`, порядок по номеру:

| Файл | Что создаёт |
| --- | --- |
| `001_create_universities.sql` | `universities` (`id`, `name`, `city`) |
| `002_create_extensions.sql` | расширение `pgcrypto` (для `gen_random_uuid()`) |
| `003_create_skills.sql` | `skills` (`id`, `name`, `category`) |
| `004_create_users.sql` | `users` (UUID, email, `password_hash`, ФИО, вуз, курс 1–6, telegram, цвет аватара) |
| `005_create_listings.sql` | enum-типы + таблица `listings` |
| `006_create_user_skills.sql` | M2M пользователь ↔ навык |
| `007_create_listing_skills.sql` | M2M анкета ↔ навык |
| `008_create_listing_roles.sql` | роли в запросе команды (`role_focus`, `slots_needed`) |
| `009_create_messages.sql` | личные сообщения (отправитель, получатель, опционально анкета) |

Enum-типы в БД:

- `listing_type`: `seeking_team`, `seeking_members`
- `listing_format`: `online`, `offline`
- `listing_status`: `active`, `closed`
- `role_focus`: `backend`, `frontend`, `fullstack`, `mobile`, `ml`, `data`, `devops`, `qa`, `design`, `pm`

Пароли в таблице `users` хранятся только как `password_hash`.

## Контракт frontend ↔ backend (важно)

Фронт и бэк **ещё не согласованы**. Не маппь молча одно на другое и не ломай демо-типы «под API» без явной задачи.

| | Frontend (демо) | Backend / БД |
| --- | --- | --- |
| id анкеты | `number` | UUID |
| тип | `person` / `team` | `seeking_team` / `seeking_members` |
| формат | `Онлайн` / `Очно` / `Гибрид` | `online` / `offline` (гибрида нет) |
| роль | свободная строка | enum `role_focus` |
| стек | строки вроде `React` | справочник `skills` + M2M |
| вуз | строка (`ВШЭ`, …) | `universities` + `university_id` у пользователя |
| автор | поля прямо в `Listing` | отдельная таблица `users` |

Стыковка API с каталогом — отдельная задача. Меняешь контракт — напиши об этом в PR.

Черновой HTML-макет лежит в `frontend/sketches/header.html`. Источник правды для сайта — компоненты в `src/`, не этот файл. Скиллы агентов: `.cursor/skills/` и копия в `.agents/skills/` (`frontend-design`, `anti-slop`). Если они спорят с этим файлом, для Dream-Team побеждает этот файл и просьба Игоря в чате.

Агент по дизайну:
- Работает только в `frontend/`. Не трогает `backend/`, `database/`, `docker-compose.yml`.
- Не подключает API и не переписывает демо-типы под бэкенд.
- Не выдумывает поля, которых нет в демо и в схеме (город, рейтинг, дедлайн, «победитель хакатона»).
- Язык интерфейса — русский. Стили — в `src/index.css`. `src/App.css` не заполнять.
- Углы карточек и кнопок небольшие (около 8–10px), не капсулы на весь прямоугольник. Круглыми остаются только значок у «Войти» и точка формата.

### Что можно обещать данными

Пока каталог на демо (`demoListings.ts`): свободная роль, бейдж текстом, проект, формат «Гибрид», вуз строкой.
